# Передача задач между чатами

## Правило маршрутизации (действует по умолчанию)

| Тип задачи | Куда | Признак |
|---|---|---|
| Код, сборка, генераторы, разметка, производительность, редиректы, аналитика | **чат разработки** | нужно менять `.js`/`.html`-генератор, `tools/*`, конфиг, бандл |
| Тексты, заголовки, FAQ, структура статьи, анкоры в тексте, новые посадочные | **чат контента** | меняются слова, а не механика |
| Привлечение аудитории, каналы, семантика, приоритеты, метрики | **этот чат (стратегия)** | нужен выбор «что и зачем», а не «как в коде» |

Правило простое: если после правки надо запускать `node tools/verify-build.js` — это разработка. Если надо писать текст — это контент. Стратегический чат не правит ни то, ни другое: он находит блокеры, ставит приоритеты и формулирует ТЗ.

## ПРОМПТ ДЛЯ ЧАТА РАЗРАБОТКИ (копировать целиком)

> Контекст: статический пререндеренный сайт kabinetdoma.ru (эргономика домашнего офиса), GitHub Pages, домен kabinetdoma.ru. Стек: React-бандл `assets/index.js`, офлайн-каталог `data/catalog.js`, генераторы в `tools/` (`prerender.js`, `fix-page.js`, `build-article.js`, `sitemap.js`, `make-redirects.js`, `seo-fix.js`). `package.json` нет — всё запускается через `node tools/<файл>.js` из корня.
>
> Жёсткие ограничения проекта (нарушение = сломанная выкладка):
> - в HTML не должно быть строки `ozon.ru` (валидатор падает);
> - цены не печатаются: `price_mode` только `hidden`/`note`, поля `price`/`priceFrom` в каталоге запрещены;
> - партнёрские ссылки: `rel="sponsored"` + видимая пометка «Реклама» с erid и рекламодателем;
> - после любых правок `node tools/verify-build.js` должен писать «всё чисто»;
> - ничего не деплоить без разрешения владельца.
>
> Задачи по приоритету:
>
> **P0. Разметка новой статьи описывает главную.** `article/kak-vybrat-kreslo-dlya-spiny/index.html` содержит блок `<!-- kd-seo -->` с `@id: https://kabinetdoma.ru/#webpage`, тайтлом и описанием главной — страница унаследовала head от `index.html` при копировании шаблона. Нужно: перегенерировать страницу штатным путём (или прогнать постпроцессор), чтобы на ней были `Article` + `WebPage` + `FAQPage` + `BreadcrumbList` с её собственным `@id`. Проверить, что `build-article.js` больше не копирует `<!-- kd-seo -->` из главной, а генерирует разметку с нуля.
>
> **P0. erid у 1 оффера из 81.** В `data/catalog.js` у 80 офферов пустые `erid` и `advertiser`. Это нарушение маркировки рекламы (347-ФЗ) и риск отключения от партнёрских программ. Нужно: добавить поля всем офферам и убедиться, что рендер (`assets/kd-catalog-render.js`) выводит пометку «Реклама» с erid рядом с каждой партнёрской ссылкой, а не только у одного товара.
>
> **P1. sitemap расходится с canonical.** `tools/sitemap.js` (появился 2026-11-02) собирает URL без завершающего слеша: `/article/kak-vybrat-kreslo-dlya-spiny`, `/articles`, `/calculator`. При этом canonical на страницах — со слешем, а `verify-build.js` требует слеш. Для Яндекса это разные адреса. Нужно: генерировать ровно те URL, что стоят в canonical (со слешем), и не терять per-URL `lastmod` для изменённых страниц.
>
> **P1. Постпроцессор не встроен в пайплайн.** `tools/seo-fix.js` проставляет выверенные `title`/`description` из `tools/seo-pages-*.json`, добавляет `Article`/`FAQPage`/`BreadcrumbList` и блок перелинковки. Он идемпотентен, но запускается вручную — после `prerender.js` его результат затирается. Нужно: вызвать его последним шагом сборки (после `prerender.js`, `fix-page.js`, `make-redirects.js`), чтобы генераторы не возвращали обрезанные описания с «…».
>
> **P1. Новая статья не попала в хаб и в метаданные.** `/articles/` — статический хаб с 17 карточками по 5 кластерам; статья про кресло не добавлена ни в хаб, ни в `tools/seo-pages-*.json`, поэтому остаётся сиротой. Нужно: добавить карточку в кластер «Кресло для спины и положение монитора» и запись с title/description в JSON постпроцессора. Это делает чат разработки по списку от контента — или, если так проще, пусть `build-article.js` сам дописывает карточку в хаб.
>
> **P2. Производительность.** Главная: 21 картинка с `images.unsplash.com` (в репозитории лежат локальные SVG, README обещает их), Google Fonts без `font-display`, бандл 1.39 МБ. При этом 107 КБ пререндеренного HTML выбрасываются, потому что приложение монтируется через `createRoot(...).render()`, а не `hydrateRoot` — LCP зависит от загрузки JS. Нужно: локальные картинки с `width`/`height` и `loading="lazy"` ниже первого экрана, `font-display: swap`, и решение по гидрации (если `hydrateRoot` ломает разметку — обосновать и оставить `createRoot`, но тогда облегчить критический CSS/JS).
>
> **P3. 17 редиректов на meta-refresh.** GitHub Pages не умеет 301. Если владелец подключит Cloudflare — заменить на `_redirects`/Rules с 301, чтобы не терять вес старых адресов.
>
> Критерии приёмки: `node tools/verify-build.js` зелёный; на всех 18 статьях `Article` + `FAQPage` с `@id`, равным URL страницы; в sitemap URL совпадают с canonical посимвольно; erid у 100% офферов; в HTML нет `ozon.ru` и нет цен.

## Что остаётся за этим (стратегическим) чатом

- Находить блокеры и раскладывать их по трём адресатам (код / контент / стратегия).
- Держать приоритеты: сначала то, что мешает индексации и деньгам, потом то, что добавляет трафик.
- Придумывать каналы привлечения и проверять их экономику (см. `PROMO-PLAN.md`, раздел 6).
- Сводить недельный отчёт по воронке «показы → визит → инструмент → клик по партнёру → доход».
