# Инструкции для агентов: kabinetdoma.ru

Один репозиторий, одна рабочая копия, несколько чатов. Этот файл — правила для всех чатов
(разработка, контент, продвижение). Роль задаёт владелец в первом сообщении; если не задана —
определи по задаче и работай по `docs/roles/<роль>.md`.

## 1. Что прочитать в начале каждой сессии

1. `docs/README.md` — карта базы знаний (что где лежит).
2. `docs/questions.md` — **обязательно**: доска задач и вопросов. Быстро: `node tools/questions.js --chat <роль>`.
   Если владелец пишет «проверь задачи» — работай по протоколу из п. 2.
3. `docs/roles/<роль>.md` — что можно и чего нельзя именно тебе.
4. По необходимости: `docs/concept.md` (продукт и правила), `docs/architecture.md`
   (как устроено, как собирать), `docs/tasks.md` (состояние и планы).

## 2. Задачи и вопросы — только через `docs/questions.md`

Это доска координации: задачи `T-NNN` с метками (`разработка`, `контент`, `продвижение`,
`деплой`, `сборка`, `блокер`), вопросы `Q-NNN` друг другу и итоги. Не переспрашивай владельца
о том, что решает другой чат, и не жди ответа в реальном времени: записал — пошёл дальше.

**«Проверь задачи».** Если владелец так написал, выполни по шагам:

1. `node tools/questions.js --chat <роль>`.
2. Смотри на **⚠ активный лок**: если в работе задача с меткой `деплой` или `сборка` —
   не собирай, не коммить и не пушь, пока лок не снят. В ответе владельцу скажи, кто держит
   лок и до какого времени.
3. Возьми первую задачу в статусе `открыта` своей роли (`**Кому:**` или без адресата):
   поставь `**Статус:** в работе` и добавь `**Взял:** <роль>, ГГГГ-ММ-ДД ЧЧ:ММ`. Для деплоя и
   сборки сразу укажи `**До:**` — сколько другие чаты ждут.
4. Закончил — `**Статус:** закрыта` и `**Итог:**`: что сделано, каким коммитом, чем проверено.
5. В ответе владельцу: что взял, что закрыл, что осталось и ждёт ли ответа (номер Q).

Правила:

- **Одна задача за раз.** В статусе `в работе` у роли может быть только одна запись — это
  проверяет `--check`. План из пяти статей — это пять задач, а не пять параллельных текстов:
  закрыл текущую, перечитал доску (`--chat <роль>`), взял следующую. Пока задача не закрыта,
  следующая не начинается (исключение — блокер: делаешь незаблокированную часть и пишешь об этом).
- **План по датам.** У задачи может быть поле `**Выпуск:** ГГГГ-ММ-ДД` — раньше этой даты её
  не берут (`--check` считает это ошибкой). Так контент выпускает статьи по графику,
  а не десяток в один день; `--chat <роль>` показывает «можно брать сейчас» и ближайшую дату.
- Один владелец на запись. Закрытые записи не удаляют, ID не переиспользуют: это журнал решений.
- Ответ на вопрос: заполнить `**Ответ:**` и поменять `**Статус:** открыт` на `закрыт`, добавить
  дату. Отвечает только адресат.
- Если реплик больше двух — это уже не вопрос, а решение: переноси его в
  `docs/concept.md` / `docs/architecture.md` / `docs/tasks.md`, а запись закрывай ссылкой.
- Если открытый вопрос блокирует задачу: сделай незаблокированную часть и в ответе владельцу
  укажи «ждёт Q-00X».
- Запись с `**Кому:** владелец` — не твоя работа, а действие владельца (доступы, кабинет,
  разрешение). Не бери её себе: перечисли в ответе в блоке «Задачи для вас» и скажи, что ждёт.
- Проверка формата, меток и просроченных локов: `node tools/questions.js --check`.

## 3. Что куда писать (не дублировать)

| Что | Куда |
|---|---|
| Продукт, аудитория, тон, монетизация, юридические правила | `docs/concept.md` |
| Устройство сайта, сборка, деплой, грабли, проверки | `docs/architecture.md` |
| Актуальное состояние, планы по ролям, блокеры | `docs/tasks.md` |
| Задачи, вопросы между чатами, лок деплоя/сборки | `docs/questions.md` |
| Правила конкретной роли | `docs/roles/*.md` |
| Планы по контенту и продвижению | `CONTENT-PLAN-*.md`, `PROMO-PLAN.md` |
| Устаревшие передачи и разовые разборы | `docs/archive/` |

Числа (статей, товаров, страниц) живут только в `docs/tasks.md` и всегда с датой. Остальные
документы на них ссылаются, а не повторяют.

## 4. Жёсткие правила проекта (нарушение = сломанная выкладка)

- `node tools/verify-build.js` должен заканчиваться словами «всё чисто: можно выкладывать».
- В HTML не должно быть строки `ozon.ru`. erid не выдумывать: только из кабинета партнёрки.
  Оффер `kind:"card"` — всегда с erid и рекламодателем, `kind:"search"` — без erid.
- Цены: только `price_mode` (`hidden`/`note`) и `price_rub`; полей `price`/`priceFrom` нет.
- `article/<slug>/index.html`, `index.html`, `sitemap.xml`, `_redirects`, `articles/index.html`
  после правки сборки — артефакты: руками не править. Хаб `/articles/` собирает
  `tools/build-hub.js` из `data/articles/*.json`; вручную правят только `data/hub.js`
  (к какому блоку отнести статью и как её назвать в списке).
- Полная сборка: `PORT=8099 node tools/build.js` (пререндер поднимает Chrome и порт).
  Перед запуском — свой лок `сборка` на доске с `**До:**` (минимум +40 минут), после — закрыть
  запись: иначе другой чат правит `data/` и артефакты параллельно с пререндером.
- `assets/index.js` — минифицированный бандл в одну строку: правки точечные, после них
  `node --check assets/index.js`. Тексты статей идут через `tools/apply-articles.js`, в бандл —
  только массив статей между маркерами `/*kd:articles:start*/` и `/*kd:articles:end*/`.
- HTML-артефакты в CRLF (`.gitattributes` → `* -text`), переводы строк не менять.
- Деплой на прод — только с разрешения владельца: `bash tools/deploy-prod.sh --push`.
  `git push origin main` обновляет рабочую копию, но не прод.
- Рабочая копия общая для всех чатов: перед коммитом смотреть `git status` и `git diff`,
  не коммитить чужие правки. Коммить только свои пути (`git add <файлы>`), не `git add -A`
  и не `commit -a`: иначе в твой коммит уедут чужие правки (так уже было в `f67685b`, `f0edce9`).
  Чужие node-процессы (8080, 8099 и др.) не убивать.
- Активный лок `деплой`/`сборка` на доске — запрет на сборку, коммит и пуш для остальных
  чатов до указанного времени `**До:**`.

## 5. Конец задачи

- Обнови `docs/tasks.md`: что сделано, что осталось, какие блокеры.
- Новые правила и грабли — в `docs/concept.md` / `docs/architecture.md` / `docs/roles/*.md`.
- Возникли вопросы к другому чату — `docs/questions.md`.
- В ответе владельцу: результат, чем проверено, что осталось открытым (номера Q), и отдельный
  блок **«Задачи для вас»** — его действия с номерами `T`/`Q`. Если таких нет — напиши «Задачи для
  вас: нет». Владелец не должен искать свои пункты в тексте.
