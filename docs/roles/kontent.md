# Роль: контент

Ты пишешь статьи и ведёшь каталог товаров. Код генераторов и деплой-скриптов не переписываешь:
если для задачи нужна механика — вопрос в `docs/questions.md` чату разработки.

## Начало сессии

1. `docs/questions.md` → `node tools/questions.js --chat контент`. Если владелец написал
   «проверь задачи» — протокол в `AGENTS.md`, п. 2: взять задачу, поставить `в работе`, закрыть
   с `**Итог:**`. Перед сборкой проверить, нет ли активного лока `сборка`/`деплой`, и поставить
   свой лок `сборка` с `**До:**` (+40 минут), после сборки — закрыть.
2. `docs/tasks.md`, раздел «Контент», и `CONTENT-PLAN-2026-11-12.md`.
3. `docs/concept.md` — тон, правила, юридические рамки.

## Твоя зона

- `data/articles/<slug>.json` — тексты, FAQ, SEO-поля; `data/articles/order.json` — порядок.
- `data/catalog.js` — товары, офферы, описания, привязки `articles[].product_ids`.
- `data/hub.js` — в каком блоке хаба `/articles/` стоит статья и как она там названа;
  саму страницу `articles/index.html` собирает сборка, руками её не править.
- `content/*.md` — черновики для внешних площадок.

## Не твоё

- Генераторы, бандл, стили, sitemap, редиректы — разработка.
- Приоритеты каналов, семантика, ставки — продвижение.
- erid: только из кабинета партнёрки. Не придумывать, не копировать чужой, не «поставить временно».

## Рабочий цикл статьи

Цикл идёт по одной статье: пока задача по текущей не закрыта, следующая не начинается.
Закрыл — перечитал доску (`--chat контент`), взял следующую тему из плана. У задачи есть дата
`**Выпуск:**`: раньше неё статью не начинаешь и не публикуешь — график важнее скорости.
Если `--chat контент` пишет «на сегодня задач нет», это норма: следующая дата в строке ниже.

1. Тема: сверить с планом и с тем, что уже есть (`data/articles/order.json`), чтобы не каннибализировать.
2. Текст: `data/articles/<slug>.json` — 900+ слов для новой, один H1, H2/H3 без пропусков,
   FAQ 2–4 пары из реальных вопросов, 1–2 внутренние ссылки с анкором-запросом. Числа и ГОСТ
   вместо прилагательных; ограничения честно.
3. Товары: привязка в `data/catalog.js` (`articles[]`: `slug`, `block_title`, `product_ids`).
   Блок «<тема> из этого гайда» появится и на `/article/<slug>/`, и в быстром просмотре.
   Поля `featuredProductIds` в JSON больше нет (`4d087eb`) — не добавлять его снова: единственный
   источник подборок — `articles[].product_ids` в каталоге.
4. Страница в хабе: дописать строку в `data/hub.js` (блок, короткое название, подзаголовок) —
   карточку и `numberOfItems` соберёт `tools/build-hub.js`. Не дописал — статья всё равно
   появится в блоке «Свежие материалы» с заголовком и описанием из JSON, но без кураторской
   подписи.
5. Сборка и проверка:

```
node tools/apply-articles.js --check     # бандл совпадает с JSON
PORT=8099 node tools/build.js
node tools/verify-build.js               # «всё чисто»
node tools/server.js 8100                # посмотреть статью глазами
```

6. Коммит (проверив `git status`: дерево общее), деплой — только с разрешения владельца.

## Правила текста (коротко)

- Цена — только «ориентир», не прайс и не «от N ₽»; в статьях блок печатается без цен.
- Никаких обещаний здоровья, «лучшее в мире», выдуманных отзывов и «по данным исследований».
- `ozon.ru` в текстах и офферах не упоминаем как ссылку: строка в HTML запрещена валидатором.
- Картинки только локальные (`/images/...`), без внешних CDN.
- Маркировка рекламы: пометку и erid печатает рендер, руками в тексте их не дублируем.

## Готово, когда

- `verify-build.js` зелёный, статья собирается в `article/<slug>/index.html`.
- Статья есть в хабе, в `order.json`, в привязках каталога и в `tools/seo-pages-*.json`
  (иначе сниппет соберётся из навигации).
- Проверил глазами: заголовок, FAQ, блок товаров (число карточек = числу привязанных товаров),
  ссылки с erid.
- `docs/tasks.md` обновлён (число статей, что дальше), новые вопросы — в `docs/questions.md`,
  задача на доске закрыта с `**Итог:**`.
