# Задачи и вопросы между чатами

Одна доска на весь проект: задачи с метками, вопросы друг другу, пометки о сборке и деплое.
Имя файла историческое (`questions.md`), здесь уже не только вопросы.

Файл локальный, для публикации не предназначен: он лежит в репозитории, но на сайт не попадает
(сборка берёт только `data/`, `assets/`, `tools/` и пререндеренные страницы).

## Одна фраза: «проверь задачи»

Владельцу достаточно написать чату «проверь задачи». Дальше чат делает ровно это:

1. `node tools/questions.js --chat <роль>` — активные задачи и открытые вопросы своей роли.
2. Смотрит на строку **⚠ активный лок**. Если лок есть (метка `деплой` или `сборка` в статусе
   `в работе`) — **не собирает, не коммитит и не пушит**, пока лок не снят; в ответе владельцу
   пишет, кто держит лок и до какого времени.
3. Берёт первую задачу в статусе `открыта`, которая его роли (`**Кому:**`) или без адресата
   (записи `**Кому:** владелец` не берёт — они для владельца). В `в работе` у роли — **только
   одна** задача: закрыл текущую, снова посмотрел доску, потом взял следующую.
   Задачу с датой `**Выпуск:**` в будущем не берёт — она ждёт своего дня (так контент
   выпускает статьи по графику, а не пачкой):
   меняет `**Статус:** открыта` на `в работе` и добавляет `**Взял:** <роль>, ГГГГ-ММ-ДД ЧЧ:ММ`.
   Для деплоя и сборки сразу ставит `**До:**` — время, до которого другие чаты ждут.
4. Работает. По завершении ставит `**Статус:** закрыта` и пишет `**Итог:**` — что сделано, каким
   коммитом, чем проверено. Закрытая запись остаётся на месте: это история.
5. В ответе владельцу перечисляет: что взял, что закрыл, что осталось и ждёт ли чего-то (номер Q).

Если задача большая и упирается в другого чата — не блокироваться: сделать незаблокированную
часть, задать вопрос ниже и указать «ждёт Q-00X».

## Метки

| Метка | Что значит |
|---|---|
| `разработка`, `контент`, `продвижение` | обычная задача этой роли |
| `деплой` | выкладка на прод: пока в работе, другие чаты не собирают и не пушат |
| `сборка` | полная сборка/пререндер идёт: не трогать `assets/index.js`, `data/`, артефакты |
| `блокер` | стоит без внешнего действия: доступы, кабинет, разрешение — обычно `**Кому:** владелец` |

Один владелец на запись. Если нужен тот же файл, а лок активен — либо ждать, либо добавить свою
запись с меткой `сборка` и не пересекаться по файлам; в ответе владельцу сказать, что коммитятся
другие изменения.

````

**Статус:** открыт
**Вопрос:** одно-два предложения, в чём именно вопрос.
**Контекст:** необязательно: файлы, цифры, ссылки на документы.
**Ответ:** —
````

Поля задачи: `Метка`, `Статус` (`открыта` / `в работе` / `закрыта`), `Кому`, `Задача`,
`Выпуск` (дата, с которой задачу можно брать: `ГГГГ-ММ-ДД` или `—`), `До` (для лока — `ГГГГ-ММ-ДД ЧЧ:ММ`, иначе `—`), `Взял`, `Итог`.
Поля вопроса: `Статус` (`открыт` / `закрыт`), `Вопрос`, `Контекст`, `Ответ`.
Заголовок задачи: `### T-NNN · <роль> · <дата>`, вопроса: `### Q-NNN · <от> → <кому> · <дата>`.

Проверка и просмотр:

```
node tools/questions.js                 # доска: активные задачи и открытые вопросы
node tools/questions.js --tasks         # только задачи (с локом)
node tools/questions.js --chat контент  # адресованное роли + активный лок
node tools/questions.js --chat владелец # только задачи владельца
node tools/questions.js --all           # вместе с закрытыми
node tools/questions.js --json          # машинный формат
node tools/questions.js --check         # формат, просроченные локи, exit 1 при ошибке
```

## Правила

- Одна задача за раз: вторую запись в `в работе` не открываем, `--check` считает это ошибкой.
- Дата выпуска — это план, а не напоминание: задачу с будущим `Выпуск` не берём раньше дня
  (`--check` поругается, если взял). Хочешь ускорить — владелец меняет дату в записи.
  План из нескольких статей — это несколько задач по очереди, а не пачка в работе сразу.
- Закрытые записи не удаляются и ID не переиспользуются.
- Больше двух реплик — это решение, а не вопрос: перенеси суть в `docs/concept.md`,
  `docs/architecture.md` или `docs/tasks.md`, закрой запись ссылкой.
- Просроченный лок (`До` в прошлом) — ошибка `--check`: закрой запись или продли время.
- Числа (статьи, товары, страницы) сюда не копируются: они в `docs/tasks.md`.
