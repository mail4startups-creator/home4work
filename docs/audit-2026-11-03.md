# Внеплановый аудит kabinetdoma.ru — 2026-11-03

Полный обход: 36 канонических страниц, 17 страниц-редиректов, ассеты, прод-поведение,
ссылочный граф, разметка, доступность. Замеры — на боевом домене (браузер + `curl`),
поэтому цифры времени приблизительные: зависят от сети и прогрева кеша.

## Что в порядке

- 23 статьи и 9 служебных страниц: у всех один H1, canonical совпадает с адресом файла,
  `lang`, viewport, og:image, description; длиннее 160 симв. описаний нет, длиннее 65 — два title.
- Битых внутренних ссылок — 0. Строк `ozon.ru` в HTML — 0. Правила erid и `price_mode`
  проходят `verify-build`.
- Картинки: 243 `<img>`, у всех есть `alt`, у контентных — `width`/`height`, 185 с `loading="lazy"`.
  Внешних картинок нет, все файлы лежат в `images/`.
- Sitemap: 32 адреса, все файлы на месте, даты не из будущего, служебные страницы исключены.
  `robots.txt` корректный, `/index.spa.html` закрыт.
- 404 отдаётся со статусом 404 и `noindex`, `/article/<slug>` без слэша — 301 на слэш.
- Разметка: `WebSite`, `Organization`, `WebPage`/`CollectionPage`, `Article`, `FAQPage`,
  `BreadcrumbList`, `ItemList`; JSON-LD валидный на всех проверенных страницах.
- Страницы-редиректы (16 старых статей + `/catalog/`) ведут на существующие адреса, цепочек нет,
  у них `noindex, follow` и canonical на цель.

## Проблемы и точки роста

### 1. Бандл — девелоперская сборка React (высокий приоритет)

`assets/index.js` — 1491 КБ, из сети 384 КБ (gzip). Внутри `jsxDEV`, devtools-хук и
dev-предупреждения React («Each child in a list…», «Cannot update a component…»), то есть
это development-сборка. Production-сборка того же кода обычно легче на 30–40 % и быстрее
исполняется на телефонах. Исходников приложения в репозитории нет (`README.md`: бандл
собирается вне репозитория), поэтому нужен доступ к исходникам — вопрос Q-005.

### 2. Google Fonts блокируют отрисовку (высокий)

Два семейства (Plus Jakarta Sans, JetBrains Mono) тянутся с `fonts.googleapis.com` на каждой
странице: внешний CSS в `<head>` без `media`/`preload`, плюс 7 файлов шрифтов. В России домен
нестабилен: при недоступности страница ждёт таймаут. Варианты: self-host woff2 (2 файла,
~60 КБ) или отказаться от веб-шрифтов в пользу системных.

### 3. Админ-скрипты на всех страницах (высокий, дёшево)

`kd-admin-catalog.js` (13,6 КБ gzip) и `kd-admin-links.js` (3,8 КБ gzip) подключены на каждой
публичной странице, хотя нужны только редактору. Это ~17 КБ gzip и два лишних запроса на каждый
просмотр. Грузить по `?admin=1` или только на `/admin`.

### 4. Изображения только JPEG (средний)

12 картинок на главной — 1595 КБ, крупнейшие по 130–165 КБ, `srcset` нет, WebP/AVIF нет.
Конвертация в WebP даёт обычно −40…−60 % без видимой разницы; `srcset` + `sizes` — ещё
меньше на телефонах.

### 5. Одна og:картинка на весь сайт (средний)

У всех статей `og:image` — общий `og-image.png` 332 КБ (PNG 1200×630). Превью в мессенджерах
и соцсетях не различаются, PNG тяжёлый. Логично ставить картинку статьи и отдавать JPEG/WebP.

### 6. www-домен не отвечает (средний, владелец)

`https://www.kabinetdoma.ru/` — соединения нет (000). Кто набирает `www.`, до сайта не доходит.
Нужна DNS-запись и редирект на основной домен.

### 7. HTTP не редиректит на HTTPS (средний, владелец)

`http://kabinetdoma.ru/` отдаёт 200, а не 301 на `https://`. Дублирование протокола и
незащищённый вход. На GitHub Pages это настройка «Enforce HTTPS» в Settings → Pages.

### 8. Мягкие редиректы (низкий, но помнить)

17 страниц-редиректов работают через `meta refresh`: поиск их понимает, но это не 301.
Настоящие 301 уже описаны в `_redirects` — они заработают только при переезде на Cloudflare.
Пока терпимо; при переезде — включить.

### 9. Метрика грузится с вебвизором (средний)

Сниппет: `webvisor:true, clickmap:true, trackLinks:true, ecommerce:"dataLayer"`. Вебвизор и
карта кликов заметно увеличивают нагрузку на страницу и вес запросов; `ecommerce` включён,
хотя `dataLayer` нигде не заполняется. Решение владельца: нужен ли вебвизор.

### 10. 404 не виден в аналитике (низкий)

На `/404.html` нет счётчика Метрики, поэтому битые внешние ссылки и опечатки в адресах не видны.
Плюс ссылки в самом 404 ведут на `/calculator`, `/builder`, `/tests`, `/checklist` без слэша —
каждый клик даёт лишний 301.

### 11. Доступность (средний, дёшево)

- Поле поиска: только `placeholder`, без `<label>` и `aria-label`.
- 11 иконочных кнопок на главной, `aria-label` есть у одной.
- Нет skip-link «к содержанию» — с клавиатуры приходится проходить всё меню.
- Пиксель Метрики с пустым `alt` — норма, к делу не относится.

### 12. Внутренняя перелинковка неровная (средний, контент)

Входящих ссылок: `rabochee-mesto-na-balkone` — 2, `udalennaya-rabota-s-rebenkom` — 2,
`ergonomika-rabochego-mesta-nastroyka`, `podemnyj-stol-kak-vybrat`, `printer-*`,
`udalennaya-rabota-v-poezdke-*` — по 4. У остальных 7–13. Исходящих у статей 9–16 — это хорошо,
а вот «сиротам» нужны ссылки из соседних текстов и из хаба.

### 13. Тонкий контент (средний, контент)

По 770–810 слов: «Кронштейн на стол», «Кронштейн и шея», «Куда поставить стол»,
«Подставка для ног», «Баланс работы». Это 2–3 минуты чтения — для конкурентных запросов мало.

### 14. Мелочи гигиены (низкий)

- `articles/index.html`: `og:description` без «Собрано по темам.» — расходится с `description`.
- Нет `theme-color` и webmanifest — иконка/цвет в мобильном Chrome произвольные.
- `index.spa.html` открыт по прямому адресу (закрыт в robots) — используется локальным сервером.
- Код входа в админку (`2026`/`admin`/`kabinetdoma`) виден в бандле. Серверных изменений нет,
  риск низкий, но дефолтный код стоит убрать.
- Security-заголовков (HSTS, CSP, X-Content-Type-Options) нет — это ограничение GitHub Pages,
  решается только переездом.
