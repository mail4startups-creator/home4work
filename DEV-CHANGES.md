## Изменения структуры и логики (мои)

### 1. `tools/seo-fix.js` — новый постпроцессор (главное)

Идемпотентный скрипт, который проходит по готовым HTML-страницам и дописывает SEO-слой. Запуск: `node tools/seo-fix.js`. Уже отработал по 29 страницам.

Что делает:

- **ключи статей**: нормализует `slug` → `/article/<slug>/` (со слешем на конце, как в canonical);
- **breadcrumbs()**: строит цепочку «Главная → База знаний → Статья» для `BreadcrumbList`;
- **buildSchema()**: собирает JSON-LD `@graph` — `Article` + `WebPage` + `FAQPage` + `BreadcrumbList`; для инструментов (`/calculator/`, `/builder/`, `/tests/`, `/checklist/`) — `WebApplication` с собственным `@id`;
- **rewriteHead()**: подменяет `title`, `description`, `og:*`, `twitter:*`, ставит `og:type=article` для статей; данные берёт из `tools/seo-pages-a/b/c.json` и `tools/seo-pages-sections.json`;
- **tailBlock()**: вставляет блок перелинковки (4 статьи + 4 инструмента + ссылка на хаб) в стилистике тёмного футера;
- **FAQPage** собирается только из реальных пар `<h4>` + `<p>` на странице, ничего не выдумывается.

Маркеры для идемпотентности: `<!-- kd-seo -->` (голова + разметка) и `<!-- kd-links -->` (блок ссылок). Повторный прогон их перезаписывает, а не дублирует.

### 2. `tools/seo-pages-a.json`, `-b.json`, `-c.json`, `-sections.json` — данные

Выверенные вручную `title` (42–62 симв.), `description` (113–149 симв.) и `related` для 29 страниц: 17 старых + 4 новых (кресло для спины, подъёмный стол, эргономика за 30 минут, удалёнка с ребёнком) + 8 разделов. Записи для статьи `kak-vybrat-kreslo-dlya-spiny` и трёх новых статей добавлены последними — до этого у них были описания, собранные из навигации («Гайды Тесты 4 Калькулятор…»).

### 3. `articles/index.html` — полноценный хаб `/articles/`

Раньше `/articles/` был редиректом на главную. Теперь это отдельная страница: 21 карточка по 5 кластерам, ссылки на инструменты, футер, собственная разметка `CollectionPage` + `BreadcrumbList` + `ItemList` (`numberOfItems 21`), свои стили. Хаб **исключён** из `seo-fix.js` (у него своя разметка) и **убран из `SECTION_MAP`** в `tools/make-redirects.js` — иначе генератор снова превращал бы его в meta-refresh.

### 4. HTML-страниц — только сгенерированные блоки

В 29 файлах появились блоки `<!-- kd-seo -->` и `<!-- kd-links -->`. Позиция блока ссылок — **после закрытия `#root`, перед `</body>`**. Внутрь `#root` вставлять нельзя: приложение монтируется через `createRoot(...).render()`, а не `hydrateRoot`, поэтому статический узел внутри контейнера React затирается при первом рендере.

## Что от вас нужно (по приоритету)

1. **Встроить `seo-fix.js` последним шагом сборки** — после `prerender.js` / `build-article.js` / `sitemap.js`. Это критично: регрессия уже случилась. После вашей сборки 8 из 21 статьи остались без `Article` и `FAQPage`, у 4 новых вернулись описания из навигации. Я восстановил, но при следующей пересборке всё слетит снова.
2. **Не править сгенерированные блоки руками** — только через `seo-fix.js` и JSON-данные, иначе следующий прогон затрёт.
3. **Sitemap: завершающий слеш.** В `tools/sitemap.js` URL собираются без слеша (`/article/slug`, `/articles`, `/calculator`), а canonical — со слешем. Нужно привести к одному виду (со слешем).
4. **erid у офферов:** сейчас у 1 из 81. Юридический риск по 347-ФЗ и риск отключения партнёрок.
5. **Метаданные новых статей:** при добавлении материала сразу заводить запись в `seo-pages-*.json`, иначе страница получит описание из навигации (так и вышло с четырьмя новыми).
